# OLTgcalls: Darwin decisions (one page)

Scope: a thin Swift wrapper over raw tgcalls on iOS, using the same layer Telegram-iOS uses internally. Pinned to Telegram-iOS `24638bc` → tgcalls `c1de088` → WebRTC `590a8b2` (`ci/telegram-ios-versions.pin`). **No iOS compile has been run.** The build host is Linux.

| # | Decision | Why (source read) |
|---|---|---|
| 1 | **Packaging: SwiftPM `binaryTarget` over `TgVoipWebrtc.xcframework`** (built by `ios/OLTgVoipXCFramework`, an `apple_static_xcframework` of `//submodules/TgVoipWebrtc:TgVoipWebrtc`). **Not** tgcalls' `Package.swift`. | tgcalls `Package.swift` declares `platforms: [.macOS(.v10_13)]`, defines `WEBRTC_MAC`, excludes `platform/darwin/iOS`, `AudioDeviceModuleIOS.h` and `VideoCameraCapturer.*`, and only adds header paths into a `SharedHeaders/` WebRTC tree that is not in the repo. It compiles tgcalls against a WebRTC built elsewhere and links nothing. Adding `.iOS` would still mean rebuilding Telegram's whole Bazel graph (WebRTC + objc sdk, RTCAudioSession, ffmpeg, opus, libvpx, boringssl, MtProtoKit) in SwiftPM. The xcframework *is* Telegram's production build of those objects. |
| 2 | **Engine = `OngoingCallThreadLocalContextWebrtc`** (`Sources/OngoingCallThreadLocalContext.mm`). No second ObjC++ shim. | That file is Telegram's ObjC++ shim. It builds `tgcalls::Descriptor`, calls `tgcalls::Meta::Create` (InstanceV2Impl 7.0.0–13.0.0), maps callbacks onto our queue, and passes signaling blobs through **byte-for-byte** (`signalingDataEmitted` → NSData copy; `addSignalingData` (Swift: `addSignaling(_:)`) → `receiveSignalingData`). Swift calls only its ObjC API. |
| 3 | **Config:** `allowP2P: true`, `connections: OLRtcServers.connections(joined.iceServers ?? CallMedia.iceServers)` (coturn STUN + TURN UDP/TCP, reflectorId 0; turns:/stuns: skipped — gap item 3, 2026-11-09, same rules as Android `OlRtcServers.kt`, pinned by `Fixtures/rtcservers.json` = `olcall/integration/testdata/rtcservers.json`), `preferredVideoCodec: "VP8"`, `allowTCP: false`, `customParameters: "{}"`, `derivedState: Data()`. | This is the exact config proven through the olcall Pion server on Linux (14/14 matrix + 5/5 cross-version cells). With no reflectors, P2P is the only way to reach the server's host candidates. The relay forwards VP8 only, and Opus is tgcalls' V2 audio codec. |
| 4 | **ADM = `SharedCallAudioDevice`** (`tgcalls_ios_adm::AudioDeviceModuleIOS`, VoiceProcessingIO, wrapped as `tgcalls::SharedAudioDeviceModule`). It is created **before** the Instance and passed as `audioDevice:`, and the Instance gets a child ADM (`createWrappedAudioDeviceModule`). | This is the custom ADM that owns the session from the first sample. `SharedAudioDeviceModuleImpl` only `start()`s on `setManualAudioSessionIsActive(true)`, which `OLCallAudioDevice` calls after AVAudioSession is active. It is Telegram's production pattern (start retries 6×500 ms, `startResultHandler` → breadcrumb). |
| 5 | **Session: manual audio.** Category comes from `+[SharedCallAudioDevice setupAudioSession]`: PlayAndRecord, **VoiceChat** mode, `MixWithOthers` + `AllowBluetoothA2DP` (+ WebRTC default `AllowBluetooth`), mono output, configured inactive. Activation is by CallKit (`didActivate` → policy) or by us (`setActive(true)`) under `audio/core/ol_session_policy.c`. | One configuration source (RTCAudioSessionConfiguration) avoids WebRTC re-applying a different category. The C policy keeps the tested behaviour: retry transient errors, wait for the interruption to end on `'!pri'`, and report the verbatim NSError code (no "log and continue"). Video calls keep VoiceChat mode (VPIO echo cancellation) and switch to the loudspeaker via `overrideOutputAudioPort(.speaker)`. |
| 6 | **Interruptions / route / reset.** Interruption → policy (began: audio off + 30 s watchdog; ended + shouldResume: reactivate). Route change → the user's speaker choice is re-asserted unless BT/headset/car/USB owns the route. `mediaServicesWereReset` → re-setup and re-run the policy from the start. | Every case leaves a breadcrumb. These are the failures field iOS calls actually hit, and none of them is left implicit. |
| 7 | **CallKit:** optional (`usesCallKit`). The app forwards `provider(_:didActivate:)` / `didDeactivate` to `OLCall.callKitDidActivate/Deactivate`. Without CallKit we activate ourselves. | Ringing/reporting stays in the existing OL flow. With CallKit, CallKit owns activation (5 s watchdog in the policy). |
| 8 | **Threading:** one serial `OLCallQueue` per call (`OngoingCallThreadLocalContextQueueWebrtc`, DispatchSpecificKey). The context is created and used only on it (the wrapper asserts `isCurrent`). Audio policy runs on its own queue. UI callbacks go to main. | Mirrors Telegram's `queue` contract. tgcalls' own threads (`StaticThreads`) never call app code directly. |
| 9 | **Video:** `OngoingCallThreadLocalContextVideoCapturer(deviceId: "")` = front camera (`VideoCameraCapturer`, AVCaptureSession, tgcalls picks the format); `"back"` = back camera. Camera turned on mid-call → `requestVideo` (tgcalls renegotiates). | The production capturer, unchanged. VP8 is encoded from it because the relay is VP8-only. |
| 10 | **Views:** `makeIncomingVideoView` / `makeOutgoingVideoView` return tgcalls' `VideoMetalView` (or the sample-buffer view where Metal is unavailable). They are placed by the existing OL screen inside its own frames (squircle). | No custom renderer. The OL UI keeps its look. |
| 11 | **Info.plist / capabilities:** `NSMicrophoneUsageDescription`, `NSCameraUsageDescription`. `UIBackgroundModes`: `audio` + `voip` (the latter only with CallKit/PushKit). No other keys. | Required to keep audio running when the app is backgrounded mid-call. |
| 12 | **Min iOS 15.0**, **arm64 only** (device arm64, simulator arm64). **No bitcode.** | 15.0 is `Telegram/BUILD` `minimum_os_version` at the pin (a build floor; the real minimum is the oldest device that passes). Xcode 14+ dropped bitcode. Intel simulators are not built. |
| 13 | **Signaling transport:** `URLSessionWebSocketTask` to `wss://<host>/v1/call` with frames `join/joined/blob/stats/hangup/bye/error/ping/pong`. Offer/answer/ice/media travel *inside* blobs as tgcalls InitialSetup/NegotiateChannels/Candidates/MediaState. The server translates them (translator; sdpbridge ↔ SDP). | Pinned by golden frames shared between Go (`olcall/integration/ios_frames_test.go`) and Swift (`OLSignalingRelayTests`). |
| 14 | **Observability:** `OLBreadcrumbs` → `POST https://<host>/v1/crumbs` only. It records len + SHA-256 prefix, never payloads, keys or tokens. **No Sentry SDK, never sentry.io.** | `docs/OBSERVABILITY.md`. One timeline with the server's crumbs. |
| 15 | **Why not NTgCalls:** it has no iOS support (assignment and handoff). The raw tgcalls Telegram ships is the only iOS engine. | — |
